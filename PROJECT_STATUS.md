# TourTicketCompare Project Status

Latest change (2026-08-04): **every rendered show card is now priced, `/api/impact/*` is token-gated, and the content editor lives on its own origin.** Four things landed after the 2026-08-03 provenance work, all verified against production on 2026-08-04. (1) **Full-board pricing.** The router attached cached snapshots to a fixed six-show prefix of each board while server-rendering the whole board, so a card past the sixth date could neither show a snapshot nor honestly report one as absent even where D1 held a fresh row — 74 of 78 cards on `/artists/olivia-rodrigo` were blank for no-JS visitors and crawlers. Each route now queries exactly the cards it renders (artist-city pages query their own city's shows, which is a *smaller* query than the old artist-wide slice and also a correct one); reads stay batched at 50 ids, so the largest board costs 2 cache reads rather than 84, and coverage on that board goes 4 priced / 74 silent → 74 priced / 4 explicitly noted. The intermediate state — where an unqueried card announced an absence the server had never established — was corrected in the same branch: a card states the unavailable case only where its lanes were actually checked, and the note names no providers (with CTAs ordered affiliate-first, listing three of four destinations read as an affiliate-leading recommendation). (2) **All four `/api/impact/*` diagnostics are `DEBUG_API_TOKEN`-gated** and 404 without the token — each proxies an authenticated Publisher API call on the account's own credentials, so none may be public; `/api/health` now reports `debugApiToken` from the same gate it describes, and automation reading catalogs through `IMPACT_CATALOG_PROXY_URL` sends the token. A proxied 404 is now treated as an auth failure rather than an empty catalog, so a blocked proxy can never look like a provider that dropped its listings and clear verified links. (3) **The `/admin` content editor moved to `admin.tourticketcompare.com`** — Sveltia keeps the signed-in user's GitHub token in `localStorage`, which is shared across an origin, and the apex runs GTM/GA; the middleware now serves the editor on that host only and 404s every editor path on the apex (bundle included), enforced by the smoke suite. ## Runtime and architecture

- Production runtime: **Cloudflare Pages Functions**. Confirmed live via `/api/health` reporting `runtime: "cloudflare-pages-functions"`.
- Source of truth: GitHub `main`. Merges to `main` auto-deploy via Cloudflare Pages Git integration.
- HTML entry: `functions/_middleware.js` delegates non-asset, non-API requests to `functions/[[path]].js`.
- Page metadata source of truth: `functions/_route-metadata.js`.
- Named route shims (`functions/artists.js`, etc.) are fallback-only while middleware is active.
- D1 bindings: `DEMAND_DB` only. (No `RATE_LIMIT_DB`, no `CLICKS_DB`.)
- `/api/shows` serves artist pages from the persisted, scheduled catalogue (PR #479). Live Ticketmaster artist discovery exists as an opt-in operations path only: it requires both the `TICKETMASTER_LIVE_ARTIST_DISCOVERY_ENABLED` runtime flag (default false) and an explicit request parameter, uses the `TICKETMASTER_API_KEY` Pages secret (configured 2026-07-15, PR #475), retains the last verified response for 36h, and serves it on Ticketmaster 429/upstream errors. Normal visitor traffic never triggers a Discovery API call.
- Impact bindings: network-level and provider-specific credentials are server-side only. SeatGeek, Vivid Seats, TicketNetwork, Ticket Liquidator, and StubHub International event lanes require runtime configuration and verified destinations; SeatGeek also has artist-level entries. SeatGeek API credentials are used only by controlled discovery/snapshot tooling. **`IMPACT_TICKETMASTER_*` is no longer read by code** and should be removed from Cloudflare. `MOCK_MODE=false` and `ALLOW_MOCK_PRICES=false`; every display lane remains source/exact-event/freshness gated.
- Diagnostics: `/api/health` is public and value-free. **Every `/api/impact/*` route (health, catalogs, products, tracking-links) requires `DEBUG_API_TOKEN` and 404s without it** (2026-08-03) — each proxies an authenticated Publisher API call on the account's own credentials. The secret is configured in production (`/api/health` reports `debugApiToken: true`, read from the same gate). `debug-seatgeek.js` is gated by the same token. Automation that reads catalogs through `IMPACT_CATALOG_PROXY_URL` must send the token; a proxied 404 is treated as an auth failure, never as an empty catalog.
- Analytics runtime config: `OUT_CLICK_ID_SUBID_ENABLED` and `OUT_CLICK_ID_SUBID_PARAM` (code default `subId1`) control whether `/api/out` appends its per-click id to the pxf.io tracking URL as an Impact SubId. Neither is set in `wrangler.toml` today, so the feature is **off** and the code defaults apply; enabling means adding the `[vars]` entry in-repo. Off means affiliate URLs are byte-for-byte what they were. Enabling is an owner decision that requires confirming the parameter name with Impact and verifying one click end to end — see `docs/COMMERCIAL_FUNNEL.md`.
- Affiliate model: **Ticketmaster affiliate is gone**—Ticketmaster redirects are plain and unmonetized. All affiliate-provider lanes fail closed when provider configuration, URL/provenance validation, or Impact tracking is unavailable.

### Price snapshot cadence

Both numeric-price lanes moved from every 8h to **every 2h on 2026-07-30**, and `DEFAULT_FRESHNESS_HOURS` moved 10h → **6h** in both snapshot scripts to match. The freshness constant must stay strictly larger than the cron interval (the display gate hides any row past `expires_at`), and it is also the hard cap on displayed staleness — 2h/6h absorbs two consecutive failed runs, more grace than either the original 4h/6h or the 8h/10h pairing, while lowering worst-case displayed age from 10h to 6h.

Evidence for the change, measured against `provider_pricing_history` (the 4h era before 2026-07-26 vs the 8h era after): doubling the interval roughly doubled the per-snapshot change rate — Vivid Seats 8.6% → 18.8%, StubHub International 9.6% → 15.9%, TicketNetwork 13.0% → 14.9%. That is ~2.3%/hour of continuous drift, so a wider cron shows visitors staler prices rather than skipping redundant writes. Average displayed age falls 4h → ~1h.

Measured state on 2026-08-04 (read-only D1): `provider_pricing_history` holds **62,181 rows across 403 distinct events**, spanning 2026-07-22T17:41Z → 2026-08-04T15:10Z — the full window since Phase 0, so the 90-day prune has not yet had anything to remove. `provider_pricing_cache` holds 394 Vivid Seats rows (329 unexpired), 368 TicketNetwork (315) and 353 StubHub International (310), with the most recent writes at 14:40–15:10 UTC that day. Both lanes are writing on cadence and the freshness gate is doing its work: roughly one row in seven is expired at any moment and is hidden rather than shown stale.

The Actions-minutes rationale recorded for the 2026-07-26 throttle (commit `311bb29`) did not apply: this repo is **public**, so GitHub-hosted standard runners are free and unbilled. The other half of that commit — the 15s/3-attempt Impact request timeout and the per-job `timeout-minutes` caps, which fixed the actual snapshot-hang problem — is independent and unchanged. The real budget is Impact API request volume: one catalog request per verified event, ~620 per full cycle across the three lanes (~7.4k/day at 2h, up from ~1.9k/day at 8h). Runs sustain ~100 requests/min today without throttling; watch the scheduled run summaries for `failed > 0` if Impact ever rate-limits.

## What is not supported

- Live inventory aggregation and "cheapest" / "guaranteed availability" claims. Approved lanes are provider-listed snapshots rather than live checkout totals; each remains fail closed unless its rights, URL, exact-event, source, timestamp, and expiry gates pass.
- **SeatGeek numeric price snapshots — permanently unavailable (owner-confirmed 2026-07-15).** SeatGeek's API returns null pricing statistics for this client (permanent limitation, not a pending entitlement); `seatgeek-price-snapshots.yml` is dispatch-only and `SEATGEEK_PRICE_DISPLAY_ENABLED` is inert because no cache rows are ever written. SeatGeek is a CTA-only provider; price comparison is served by Vivid Seats, TicketNetwork, and StubHub International. Full evidence: `reports/status-history/2026-07-17-audit-reconciliation.md`.
- Tour or individual event landing pages. (City, venue, and artist-city aggregation pages **are** supported — see above.)
- Artist-level Vivid Seats CTAs. Event-level Vivid Seats CTAs are supported and live.
- Ticket Liquidator listed-price snapshots while its Impact catalog omits numeric `CurrentPrice`. StubHub US/Canada is not part of the StubHub International integration.
- Ticketmaster affiliate/tracking of any kind (the site is no longer in the Ticketmaster affiliate programme).
- `Event` / `MusicEvent` schema on any page without verified event-level data.
- **Conversion and revenue attribution.** Checkout happens on the provider's site, so the funnel ends at "left through a monetized link". Whether a click became a purchase, at what price, and what commission resulted exist only in Impact's dashboards. The funnel report never prints a conversion or revenue figure and must not be extended to invent one (`docs/COMMERCIAL_FUNNEL.md` → What cannot be measured).

## How to update this file

Refresh when any of the following change: artist count, indexing status, event count, guide count, bindings, validation pipeline, daily automation, or the set of active issues. Recount from the data files rather than trusting prior text — this file has drifted more than once. `npm run status:validate` recounts the deterministic figures from source and lists any divergence; `npm run status:validate:write` rewrites the enforced numbers and the whole per-artist table, `last_verified_at` included. `npm run status:surface:write` regenerates the two `<!-- generated:… -->` blocks (route surface, empty boards) from a real render of every route — never hand-edit inside those markers, the next run will overwrite you. Both run daily in `daily-audit.yml`, so in practice this file arrives already current: what is left for a human is prose, tour names, and anything sourced from `/api/health` or D1. When a risk resolves or a dated review concludes, distill any live residue here (or into `BACKLOG.md`), then move the narrative to a dated file under `reports/status-history/` or delete it to git history — keep this file current-state only. Reference `BACKLOG.md` for prioritised work — do not duplicate the priority list here. See `docs/DOCS_MAINTENANCE.md` for the canonical-file map.
