## Runtime and architecture

- Production runtime: **Cloudflare Pages Functions**. Confirmed live via `/api/health` reporting `runtime: "cloudflare-pages-functions"`.
- Source of truth: GitHub `main`. Merges to `main` auto-deploy via Cloudflare Pages Git integration.
- HTML entry: `functions/_middleware.js` delegates non-asset, non-API requests to `functions/[[path]].js`.
- Page metadata source of truth: `functions/_route-metadata.js`.
- Named route shims (`functions/artists.js`, etc.) are fallback-only while middleware is active.
- D1 bindings: `DEMAND_DB` only. (No `RATE_LIMIT_DB`, no `CLICKS_DB`.)
- `/api/shows` serves artist pages from the persisted, scheduled catalogue (PR #479). Live Ticketmaster artist discovery exists as an opt-in operations path only: it requires both the `TICKETMASTER_LIVE_ARTIST_DISCOVERY_ENABLED` runtime flag (default false) and an explicit request parameter, uses the `TICKETMASTER_API_KEY` Pages secret (configured 2026-07-15, PR #475), retains the last verified response for 36h, and serves it on Ticketmaster 429/upstream errors. Normal visitor traffic never triggers a Discovery API call.
- Impact bindings: network-level and provider-specific credentials are server-side only. SeatGeek, Vivid Seats, TicketNetwork, Ticket Liquidator, and StubHub International event lanes require runtime configuration and verified destinations; SeatGeek also has artist-level entries. SeatGeek API credentials are used only by controlled discovery/snapshot tooling. **`IMPACT_TICKETMASTER_*` is no longer read by code** and should be removed from Cloudflare. `MOCK_MODE=false` and `ALLOW_MOCK_PRICES=false`; every display lane remains source/exact-event/freshness gated.
- Affiliate model: **Ticketmaster affiliate is gone**—Ticketmaster redirects are plain and unmonetized. All affiliate-provider lanes fail closed when provider configuration, URL/provenance validation, or Impact tracking is unavailable.

### Price snapshot cadence

Both numeric-price lanes moved from every 8h to **every 2h on 2026-07-30**, and `DEFAULT_FRESHNESS_HOURS` moved 10h → **6h** in both snapshot scripts to match. The freshness constant must stay strictly larger than the cron interval (the display gate hides any row past `expires_at`), and it is also the hard cap on displayed staleness — 2h/6h absorbs two consecutive failed runs, more grace than either the original 4h/6h or the 8h/10h pairing, while lowering worst-case displayed age from 10h to 6h.

Evidence for the change, measured against `provider_pricing_history` (the 4h era before 2026-07-26 vs the 8h era after): doubling the interval roughly doubled the per-snapshot change rate — Vivid Seats 8.6% → 18.8%, StubHub International 9.6% → 15.9%, TicketNetwork 13.0% → 14.9%. That is ~2.3%/hour of continuous drift, so a wider cron shows visitors staler prices rather than skipping redundant writes. Average displayed age falls 4h → ~1h.

The Actions-minutes rationale recorded for the 2026-07-26 throttle (commit `311bb29`) did not apply: this repo is **public**, so GitHub-hosted standard runners are free and unbilled. The other half of that commit — the 15s/3-attempt Impact request timeout and the per-job `timeout-minutes` caps, which fixed the actual snapshot-hang problem — is independent and unchanged. The real budget is Impact API request volume: one catalog request per verified event, ~620 per full cycle across the three lanes (~7.4k/day at 2h, up from ~1.9k/day at 8h).
