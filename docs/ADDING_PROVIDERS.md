# Adding a New Ticket Provider

Gated workflow for adding a ticket provider to TourTicketCompare. Mirrors the artist onboarding model: no live CTAs until human-verified URLs are confirmed.

**Currently parked:** SeatGeek and Vivid Seats. Do not use this workflow for either unless a separate explicit scope clears the BACKLOG.md parking note.

See [docs/PROVIDER_DATA_POLICY.md](PROVIDER_DATA_POLICY.md) for provider-specific data policy and affiliate rules.

---

## Phase overview

```
[ PROPOSAL ] → gate 1 → [ CONFIGURE ] → gate 2 → [ ACTIVATE ]
```

Each gate is a human checkpoint. AI must not proceed past a gate without human confirmation.

---

## Phase 1 — Proposal

**Who:** Human.

Complete all fields before touching any file. If a field cannot be filled, the proposal is incomplete — do not proceed.

| Field | Requirement |
|-------|-------------|
| Provider name + slug | Official name; URL-safe slug (e.g. `seatgeek`) |
| Verified destination URL | Opened in browser today; confirms live and correct |
| Destination hostname | e.g. `seatgeek.com` — will be added to `allowedDestinationHosts` in `out.js` |
| Affiliate arrangement | Impact programme ID confirmed, or direct link permitted in writing |
| Artist scope | Which specific artists will get CTAs in Phase 3 (list slugs) |
| Constraint notes | Regional domains, name ambiguity, any BACKLOG parking note covering this provider |

**Gate 1 — human must confirm all before Phase 2:**

- [ ] Destination URL opened in browser — confirmed live, correct artist, no redirect to unrelated page
- [ ] Hostname is not `localhost`, `example.com`, or any placeholder pattern
- [ ] Affiliate arrangement confirmed (Impact programme ID available, or direct link permitted)
- [ ] Provider is not in `BACKLOG.md § Explicitly parked`
- [ ] No other provider-addition PR is open or in progress

---

## Phase 2 — Configure (no live CTAs)

**Who:** AI (after Gate 1 cleared).

No CTA appears yet. `public_enabled: false` is the safe default throughout this phase.

**Files that change:**

| File | What changes |
|------|-------------|
| `functions/api/out.js` | Add provider hostname to `PROVIDERS.<slug>.allowedDestinationHosts`. Do NOT add a `VERIFIED_TICKET_LINKS` entry. |
| `public/data/catalog.json` | Add `ticket_links[]` entry per artist in scope: `verified: false`, `public_enabled: false` |

**Do NOT touch** `public/data/artists.json`, `functions/api/shows.js`, or `functions/api/signup.js` in this phase.

**Validation (all must pass):**

```bash
node --check functions/api/out.js
node scripts/smoke-prelaunch.mjs
git diff --check
```

**Gate 2 — human must confirm all before Phase 3:**

- [ ] Configure PR merged and deployed
- [ ] `GET /api/out?artistSlug=<slug>&provider=<provider>` returns `link_not_found` or `provider_not_configured` — not a live 302 redirect
- [ ] No CTA button visible on any artist page
- [ ] Smoke checks pass
- [ ] Destination URL re-confirmed live in a browser on the day Phase 3 begins

---

## Phase 3 — Activate (live CTAs)

**Who:** AI (after Gate 2 cleared).

The `VERIFIED_TICKET_LINKS` entry and `public_enabled: true` must land in the **same PR**. Never set `public_enabled: true` without a corresponding `VERIFIED_TICKET_LINKS` entry.

**Files that change:**

| File | What changes |
|------|-------------|
| `functions/api/out.js` | Add `"<artist-slug>:<provider-slug>"` entry to `VERIFIED_TICKET_LINKS` with the confirmed URL |
| `public/data/catalog.json` | Update `ticket_links[]` entry: `verified: true`, `public_enabled: true`, `affiliate_enabled: true`, `last_checked_at: <today>` |
| `public/data/artists.json` | Update: `verified_provider_count`, `verified_providers[]`, `last_verified_at: <today>` |
| `functions/api/shows.js` | Add artist slug + provider URL to the provider's affiliate links map |
| `public/index.html` | Regenerated by `npm run events:sync` |

**Validation (all must pass):**

```bash
node --check functions/api/out.js
node --check 'functions/[[path]].js'
python3 scripts/validate-events.py --for-production
node scripts/smoke-prelaunch.mjs
npm run events:sync
git diff --check
```

**Gate 3 — human must confirm all:**

- [ ] Activate PR merged and deployed
- [ ] `GET /api/out?artistSlug=<slug>&provider=<provider>` returns 302 to the expected destination
- [ ] CTA button appears on the artist page; `href` in page source is `/api/out?...`, not a raw affiliate URL
- [ ] `npm run artist:check -- <slug>` exits 0 (PASS) for each artist in scope
- [ ] `npm run test:mvp` passes

## Impact affiliate setup (if applicable)

If the provider uses Impact:

- Set `affiliate_enabled: true` in the `catalog.json` `ticket_links[]` entry.
- Add the Impact programme ID as an environment secret in the Cloudflare dashboard (e.g. `IMPACT_<PROVIDER>_PROGRAM_ID`). Never add it to source code or documentation.
- The Impact Publisher Tag (`public/impact.js`) handles client-side link transformation for `ticketmaster.com` automatically. For other providers, pre-minted Impact shortlinks may be required unless Publisher Tag support is explicitly configured for the provider's hostname.
